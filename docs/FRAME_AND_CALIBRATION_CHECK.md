# 坐标系定义与标定验收规范 (docs/FRAME_AND_CALIBRATION_CHECK.md)

**文档版本**：v1.0  
**状态**：Released  
**关联里程碑**：RM-M5 / RM-SPEC-05  

本文档规定了 `ros2-moveit-pybullet-bridge` 系统中的统一坐标系命名、转换契约和手眼标定验收方法，以消除 Sim2Real 迁移中的空间几何偏差。

---

## 1. 核心坐标系定义 (Frame Definition)

系统主要包含以下 7 个核心坐标系，其 TF 树关系与功能定义如下：

```
                 [world] (世界/大底座坐标系)
                    |
               [base_link] (机器人底座坐标系)
                    |
                [ee_link] (机器人末端法兰坐标系)
                    |
                 [tool0] (末端零点，力传感器安装位)
                    |
              [gripper_tcp] (夹爪控制中心点)
             /             \
    [camera_frame]    [object_frame] (目标物体坐标系)
     (手眼相机坐标系)
```

1. **`world`**: 世界坐标系，通常以机械臂底盘座投影在水平地面的中心点或外部环境的固定基准为原点，Z轴垂直朝上。
2. **`base_link`**: 机器人本体底座坐标系，作为机器人运动学计算的起点。对于 Franka Panda，其原点位于 `panda_link0`。
3. **`ee_link`**: 机械臂最后一个运动关节输出法兰坐标系，即逆运动学（IK）求解的末端目标点。
4. **`tool0`**: 六维力/力矩（FT）传感器安装平面坐标系。
5. **`gripper_tcp`**: 夹爪工具控制中心点（Tool Center Point）坐标系。原点位于夹爪双指闭合时的几何中心线中点，Z轴指向夹爪前方夹紧方向。
6. **`camera_frame`**: 手眼相机（Wrist Camera / Hand Camera）坐标系。原点位于图像传感器光心，Z轴指向相机正前方，X轴指向右侧，Y轴指向下方。
7. **`object_frame`**: 被操作目标物体（如红色方块等）的质心坐标系。

## 2. 空间契约与数据约定 (Conventions)

为确保异种数据（MoveIt、PyBullet、神经网络策略）的几何对齐，空间变换定义需严格遵守以下行业REP规范：

* **单位约定**: 
  * 长度/距离单位统一为 **米 (m)**。
  * 角度/转角单位统一为 **弧度 (rad)**。
  * 关节位置：旋转关节统一为弧度，移动/伸缩关节统一为米。
* **四元数表达格式**: 统一为 **`[x, y, z, w]`**（遵循 ROS 2 tf2 及 geometry_msgs 的序列化定义）。
* **手性与坐标轴方向**: 遵循 **REP-103** 规范，采用右手坐标系。
  * X轴：指向前上方（前向/接近方向）。
  * Y轴：指向左侧。
  * Z轴：指向正上方。
* **时间戳对齐**: ROS Header Stamp 的秒和纳秒必须严格单调递增，禁止由于进程间乱序出现时间倒流或延迟错位（允许偏差范围在 ApproximateTime 窗口内）。

## 3. TF 树几何健全性校验 (Sanity Tests)

在接入真实硬件或执行 PolicyRunner Replay 之前，系统必须通过以下静态与动态 TF 几何合理性检测：

### TF-01: Quaternion Norm Check (四元数归一化)
* **检查标准**: 从 TF 获取的任何旋转四元数 $q = [x, y, z, w]$，其模长必须满足：
  $$\left| \|q\|_2 - 1.0 \right| < 10^{-5}$$
* **风险评估**: 模长异常会导致逆运动学解算时雅可比矩阵计算奇异值爆炸，引起关节突增和碰撞。

### TF-02: Base-to-EE Kinematic Chain Validation (运动学链一致性)
* **检查标准**: 通过 `tf2_ros` 监听 `base_link -> ee_link` 变换，并与 `SimSource` 的 PyBullet 正向运动学（FK）输出进行比对，三维欧氏距离偏差：
  $$\Delta d = \| \mathbf{p}_{tf} - \mathbf{p}_{fk} \|_2 < 1\text{mm}$$
* **风险评估**: 偏差过大说明 URDF 定义或关节标定零偏存在误差。

### TF-03: Static Drift Verification (手眼相机漂移评估)
* **检查标准**: 在机械臂保持静止的 `HOLD` 姿态下，读取 `camera_frame -> object_frame` 的位姿估计。在连续 100 帧观测中，位置的方差和最大漂移值需满足：
  $$\text{Var}(\mathbf{p}) < 10^{-6}\text{m}^2, \quad \max(\|\mathbf{p} - \bar{\mathbf{p}}\|_2) < 2\text{mm}$$
* **风险评估**: 漂移过大说明感知节点的降噪或标定矩阵不稳，抓取动作容易挥空或抓偏。

## 4. 手眼标定验收方法 (Eye-in-Hand Calibration Protocol)

针对手眼相机（Wrist-mounted Camera），使用 **5 点法标定板** 验收标准如下：

1. **测试采样点**: 在标定板前上方设计 5 个不同姿态与距离的采样位姿，使标定板位于图像中心且无严重反光。
2. **标定残差（Calibration Residual）**:
   * 位置重投影残差均值需 $< 1.5\text{mm}$。
   * 姿态重投影角度残差均值需 $< 0.01\text{rad}$。
3. **TCP 旋转一致性检查**: 围绕 TCP 轴点执行旋转（Pitch / Yaw $\pm 15^\circ$），相机观测的目标特征点重构空间位置的最大极差不能超过 $2\text{mm}$。

## 5. 机械臂操作 TF 与移动导航 NAV2 TF 的差异对比

虽然本项目与 `Nav2` 导航堆栈底层都基于 ROS 2 的 `tf2` 库，并在数学表达和树状拓扑规则上完全一致，但在实际应用架构中存在显著差异：

| 比较维度 | 本项目（机械臂操作） | Nav2（移动导航） |
| :--- | :--- | :--- |
| **拓扑树结构** | **深而长**：呈高维度的线性串联运动学链（如 `base_link -> link1 -> ... -> link7 -> tool0 -> tcp`）。 | **扁而宽**：呈放射状结构（如 `map -> odom -> base_link -> laser_frame/camera_frame`）。 |
| **主要空间维度** | **完全 6-DOF**：平移（X/Y/Z）与旋转（Roll/Pitch/Yaw，四元数）同样关键。 | **通常是 2.5D**：重点关注平面位置（X, Y）以及朝向角（Yaw）。 |
| **动态变换更新源** | 主要是 `robot_state_publisher`。基于高频 `/joint_states` 反馈与 URDF，利用**正向运动学（FK）**计算并发布关节链变换。 | 主要是定位与状态估计节点。`odom -> base_link` 由里程计/IMU融合节点发布；`map -> odom` 由 SLAM/AMCL 节点修正。 |
| **累计漂移与连续性** | 关节间变换物理关系极强，精度依赖电机编码器，不随时间产生累积漂移，保证高连续性。 | `odom` 存在累积物理漂移，需要 `map -> odom` 不定期进行定位修正跳变，以提供绝对定位精度。 |
| **标定与精度要求** | 极高，重点在**手眼标定 (Eye-in-Hand)** 和 **TCP偏置**。允许残差通常在**毫米级 ($<1.5\text{mm}$)**。 | 较低，重点在传感器相对于机器人底座的安装偏置。允许残差通常在**厘米级**。 |
| **控制环路影响** | 动作输出通常为高精度的空间 delta 位姿，对微小误差和四元数不归一引起的奇异值极其敏感。 | 控制输出为底座速度指令（`cmd_vel`），避障和路径规划对微小传感器坐标误差容忍度较高。 |
