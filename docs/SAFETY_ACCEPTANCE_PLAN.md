# 安全验收与故障恢复计划 (docs/SAFETY_ACCEPTANCE_PLAN.md)

**文档版本**：v1.0  
**状态**：Released  
**关联里程碑**：RM-M5 / RM-SPEC-06  

本文档定义了真实机械臂接入时的系统安全验收准则与各类故障状态下的手动/自动恢复规程，确保物理系统的绝对安全。

---

## 1. 安全级别与制动模式定义

真实机械臂物理上电运行时，安全机制将分为以下五个层次（由软到硬）：

### 1.1 软件 HOLD (Software Hold)
* **执行主体**: ROS 2 仿真桥 `pybullet_bridge` / 真实驱动节点。
* **触发条件**: 动作指令中断超过看门狗超时阈值（如 500ms）。
* **动作行为**: 节点自动停止下发新轨迹，计算并发布原位锁死轨迹（以当前关节角度反馈作为目标），关节保持在当前位置伺服锁定。

### 1.2 软件快速停止 (Software Quick Stop / Deceleration)
* **执行主体**: 实机控制器/驱动器层（如 CANopen DS402 状态机）。
* **触发条件**: 触发 R1/R2 等异常警报，或轨迹轻微越限（超出软限位）。
* **动作行为**: 依据预设最大加速度曲线进行受控减速，停止后进入 Operation Enabled 或 Quick Stop Active 状态，抱闸不关闭，电机继续带电保持。

### 1.3 控制器故障熔断 (Controller Fault / Disable)
* **执行主体**: 底层电机驱动器。
* **触发条件**: 电机过载、轮廓误差超限（Following Error）、过流/过压。
* **动作行为**: 驱动器切断输出电流（Switch On Disabled），刹车抱闸瞬间闭合锁死，防止重力下沉。

### 1.4 操作员停止 (Operator Stop)
* **执行主体**: HOC 运维控制台。
* **触发条件**: 操作员在 Web 界面按下软急停或发出暂停请求。
* **动作行为**: 触发 ROS 服务切入 HOLD 状态或下发零速度指令。

### 1.5 硬件急停 (Hardware E-Stop)
* **执行主体**: 物理安全回路 / 双通道安全继电器。
* **触发条件**: 操作员按下物理急停按钮，或围栏光幕触发。
* **动作行为**: **物理切断**马达驱动器的三相高压母线电源。抱闸因失电瞬间紧急闭合。这是不受任何软件控制的最终物理屏障。

## 2. 软件熔断安全状态切换 (R0 - R3)

系统基于 `risk_engine` 定义了四个风险等级（R0至R3），其响应机制与恢复逻辑如下表所示：

| 级别 (Level) | 状态定义 | 触发原因 | 预期安全动作 | 恢复机制 (Recovery) |
|---|---|---|---|---|
| **R0** | Normal (正常运行) | 状态估计在噪底内，时延与漂移指标正常 | 持续执行神经网络与 MoveIt 轨迹 | 无需恢复 |
| **R1** | Warning (警告) | 传感器噪声增大，系统时延接近临界值 | HOC 闪烁黄色警报，控制器正常运行 | 状态转好后自动消除 |
| **R2** | Degraded (降级运行) | 发现分布偏移，MMD 或 KL 散度超限 | 控制器减速运行（以 50% 速度下发） | 漂移消除后自动恢复，或由操作员确认恢复 |
| **R3** | E-Stop (系统熔断) | 通信完全断开、指令突变超限、安全状态异常 | 立即下发 HOLD 轨迹，清空队列，锁死关节 | 必须执行 **“操作员确认复位”** 流程 |

## 3. 安全验收用例与测试计划

### SF-01: Command Timeout (指令看门狗)
* **测试目的**: 验证当神经网络策略或 MoveIt 节点异常退出或卡死时，机械臂能安全 HOLD。
* **操作步骤**:
  1. 启动 `PolicyRunner` 与 `pybullet_bridge`，使机械臂处于 Replay 状态。
  2. 模拟通信中断（向 PolicyRunner 进程发送 `SIGSTOP` 信号）。
* **预期结果**:
  * 桥接节点检测到 `/bridge/command` 无更新，耗时超过 `watchdog_timeout_ms`。
  * 桥接节点输出 `Watchdog HOLD` 日志，机械臂保持在中断处的姿态，不再响应旧动作。
* **通过标准**: 运动在 500ms 内完全受控锁死，未发生关节倾坠或失控飘移。

### SF-02: Stale Joint State (传感器丢失防护)
* **测试目的**: 验证反馈关节状态缺失时，安全层能自动保护。
* **操作步骤**:
  1. 停止 `/bridge/sim/joint_states` 话题的发布。
  2. 尝试下发新的规划轨迹或 Replay 指令。
* **预期结果**: `risk_engine` 检测到状态反馈断流，评估风险为 R3，拒绝并丢弃所有下发的控制指令。
* **通过标准**: 拒绝下发指令，系统切换至安全熔断模式。

### SF-03: Trajectory Limit Rejection (超限拦截)
* **测试目的**: 验证当输入指令超出关节极限或加速度限幅时，动作适配器能软截断。
* **操作步骤**:
  1. 向适配器注入包含关节超界的目标位姿。
  2. 注入包含关节角度瞬间跳变（例如从 0 rad 突变为 1.5 rad）的动作。
* **预期结果**:
  * 适配器输出 `Panda delta_xyz exceeds limit` 或限速限幅启动。
  * 输出关节指令被 Clamp 在安全阈值内，并向 `/system_health` 发布警告。
* **通过标准**: 指令输出曲线平滑过度，无突跃下发。

## 4. 操作员确认复位与恢复流程 (SOP)

当系统发生 R3 级别熔断后，必须遵循以下步骤进行安全复位：

```
+------------------+     1. 物理安全检查     +-------------------+
|  系统处于 R3 状态  | ----------------------> |  操作员现场确认环境 |
+------------------+                           +-------------------+
                                                         |
                                                         | 2. 复位硬件/急停
                                                         v
+------------------+    4. 低速回 Home 姿态    +-------------------+
|  系统重新处于 R0   | <---------------------- | 发送 /reset_sim   |
+------------------+                           +-------------------+
```

1. **故障排查**: 操作员必须先在 HOC 看板或日志中排查熔断原因（如 `distribution_shift` 或 `watchdog_timeout`）。
2. **物理复位**: 若触发了硬件急停，操作员确认工作空间无碰撞风险后，手动旋转释放物理急停旋钮，并复位安全继电器。
3. **软件复位 (Acknowledge)**:
   * 在 HOC 界面点击 "Acknowledge Safety Alert" 按钮，或调用接口：
     ```bash
     ros2 service call /bridge/reset_simulation std_srvs/srv/Trigger
     ```
4. **低速回 Home**: 系统复位后，默认以 10% 的低速限速指令驱动机械臂回到预设的安全 Home 位置。
5. **就绪度重检**: 机械臂回到 Home 姿态后，系统自动执行一次静态的 TF 与状态传感器自检，确认无零漂和丢包，方可重新接收新任务。
